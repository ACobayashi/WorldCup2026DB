# 比赛首发阵容图

由韩羽宸维护。比赛详情增加绿茵阵容图，覆盖本届全部 104 场、208 套阵型及 2,288 个首发站位。桌面横向、窄屏纵向显示同一组来源坐标。圆标显示真实球衣号，采用 48 个国家队的主题配色；这不是当场实穿球衣的复刻。门将使用橙色标记，队长标记 C。点击球员直接进入该场个人表现。

球场内及鼠标提示均使用已核对数据源的中文名；英文名只在球员详情页用于中英文对照。进球、乌龙、黄红牌、换下分钟复用已有数据库事件；未补编评分、身价、平均年龄或其他缺失数据。图中展示比赛开始时的首发，不随换人生成未经核实的实时阵型。原有首发/替补大头照名单、技术统计和事件记录继续保留。

## 来源核验

已提交的 `data/worldcup/formations.json` 保存阵型、球员 ID、号码、坐标、队长、原比赛链接与原响应 SHA-256。来自懂球帝本届赛季 `26123` 的 `persons.team_A/team_B.formation` 及 `lineups`；逐场匹配 FIFA 赛季 `285023` 的两队、开球时间、赛果和点球比分。每队 11 名首发必须与已导入 FIFA 首发完全相同。球员通过“本届球队 + 唯一号码”核对，已有大头照映射的球员还需懂球帝 ID 一致，拒绝重复球员、越界坐标、异常阵型和错队。

懂球帝 `score_A/B` 在点球场次可能包含点球大战，核验使用 `fs_A/B` 比较比赛终场比分、`ps_A/B` 比较点球比分。已有 `home_score_et/away_score_et` 表示加时结束时累计比分，不再叠加 90 分钟比分。

坐标为数据源的阵型示意位置，不是比赛中的平均位置或追踪数据。阵型字符串直接沿用源数据，不用 GK/DF/MF/FW 人数猜阵型。原始完整响应位于被忽略的 `tmp/player-headshot-sources/`；提交的是本功能所需字段及校验依据，不导入其全部技术统计。

## 实现与复现

没有新增数据库表或列。`Formation` 模型通过既有 `wc_source_mappings` 将快照的 FIFA ID 与实际数据库比赛、球队和球员关联；每次显示重新检查当前数据库首发与号码。数据不一致、缺少阵型或快照时提示未核实，仍显示原来的球员名单，不生成替代站位。控制器、模型和视图分别处理路由、核对、绘图。

普通新机器使用已提交快照即可，无需联网抓取站位。需要重新采集时执行 `python scripts/worldcup_formations.py`（复用照片脚本的 Python/Pillow 环境）；下载 10 个轮次和 104 场阵容，有缓存、有限并发与失败重试。源码中保存精确匹配规则，不做模糊姓名合并。清洗完成后一次性写入快照，不改数据库。

```powershell
python -m unittest discover -s tests -p test_worldcup_formations.py
php scripts/check-worldcup-formations.php
php scripts/check-worldcup-pages.php
```

验收覆盖全部比赛首发、坐标和事件归属，错误号码、错误球员 ID、重复/缺失首发、非法坐标与阵型拒绝。数据库校验临时修改一名首发以验证过期站位拒绝，事务最终回滚。浏览器检查桌面及 412 像素窄屏，实际点击球员后核对选中决赛。预览见 `docs/screenshots/match-formation.jpg`。
